## 优化方案

### 1. 修复 ping/连通性测试弹出 CMD 黑框
- 新增 `internal/engine/latency_windows.go`（`//go:build windows`）与 `internal/engine/latency_unix.go`（`//go:build !windows`），分别定义 `sysProcAttrNoWindow()`：Windows 返回 `&syscall.SysProcAttr{HideWindow: true, CreationFlags: 0x08000000 /*CREATE_NO_WINDOW*/}`，其他平台返回 nil
- `internal/engine/latency.go` 的 `pingSamples()` 中 `exec.CommandContext` 改为先赋值 `cmd`，设置 `cmd.SysProcAttr = sysProcAttrNoWindow()` 再 `Output()`——这一处覆盖延迟测量、节点列表快速 ping、单节点 ping 全部场景（它们都走 `pingSamples`）

### 2. 引擎：延迟/抖动实时推送
- `internal/engine/types.go`：`Progress` 增加可选字段 `LatencyMS *float64`、`JitterMS *float64`（JSON omitempty，向后兼容）
- `internal/engine/engine.go`：`RunTest` 中 `MeasureLatency` 完成后额外发一条 `Progress{Stage: "latency_done", LatencyMS/JitterMS}`，前端实时面板即时显示时延/抖动徽标（IPv6 轮开始时自动刷新）

### 3. 前端：仪表盘 + 趋势图 + 实时数字（浅色主题风格）
- 新增 `frontend/src/components/SpeedGauge.tsx`（纯 SVG，浅色）：
  - speedtest.net 式非线性刻度 `[0, 5, 10, 50, 100, 250, 500, 750, 1000]` 均匀分布在 270° 弧上，分段线性插值求角度；>1000Mbps 指针钳制在末端、数字仍显示真实值
  - 浅灰轨道弧 + 青绿进度弧（下行 `--chart-1` 青、上行 `--chart-2` 橙，随阶段切换）、深灰指针（CSS transition 平滑转动）、刻度数字标注
  - 中心下方大号实时数字（tabular-nums）+ 单位 Mbps + 方向图标（↓/↑）+ 阶段名
- 重排 `frontend/src/pages/SpeedTestPage.tsx` 实时面板：
  - 布局 `grid lg:grid-cols-[300px_1fr]`：左仪表盘（实时跳动数字）、右现有 `SpeedChart` 趋势图，高度对齐（约 260px）
  - 面板头部：当前阶段徽标 + 时延/抖动徽标（来自 `latency_done` 事件，测完即显示）
  - 结果视图保持不变（大数字卡片 + 全量曲线）

### 4. 验证
- `go vet ./... && go test ./...`；`wails build` 出 exe
- `wails dev -browser` + 浏览器自动化跑一轮完整测速：确认全程无黑框（引擎侧已从根上消除窗口创建）、仪表盘指针/数字实时跳动、趋势图与时延徽标正常，截图核对浅色视觉
- 完成后提交推送
